## 实时互动层方案设计（未开工，仅设计）

写了 `docs/realtime-plan.md`，覆盖主持人四模式 / 学员跟随 / 实时统计 / 门槛与分支。

核心判断（这条最重要）：
- 现有 `Trace` 是**对等广播**（各客户端自持 `S` 状态互发事件），撑不住 50 人。
  必须改成 **server-authoritative**：客户端发意图，服务器裁决后广播事实。
- 主持人四模式（Demo/Dashboard/Review/Control）是 **host-local UI 状态**；
  房间里另有全局 `phase`。两者必须分开存，否则会做出"切模式把学员也切了"的 bug。
- 50 人根本不是性能问题（20 题 × 50 人 ≈ 1000 条消息）。真正风险是现场网络，
  所以 **LAN 局域网模式是一等公民，不是 nice-to-have**。
- 选型上明确建议**不要上 Cloudflare Durable Objects**——DO 的价值在百万房间弹性，
  这个量级用不上。推荐内地 2C4G 轻量云 + Node ws 单进程。

已定位的现存缺陷（改造时逐个修）：
- `Trace.seen[_n]` 超过 600 条会清空 → 长会话旧消息被重复应用。要换 `seq` 单调序号 + `welcome` 全量快照。
- 投票按 `Trace.cid`（sessionStorage）记 → 无身份、换设备算两人，做不到"看到是谁"。
- `goto()` 人人可调 → 学员端必须禁用，只接受 `nav` 事实。
- `n.poll` 一页一个、无开关态 → 要扩成 `widgets[]` + 开题/收题/倒计时。
- 规格无 gate / branch → 需求里的顺序限制与分支走不了。

改造落点映射（函数级）已写进文档第 1 节表格。

待用户拍板 7 件事：部署形态、身份强度、self 分支下"固定死"的语义、
匿名模式、数据留存、终端形态、并发上限。

## 中位数（已落地）

用户要求评分统计"平均以外还要有中位数"。已实装：
- `src/flowdeck.js` 新增 `median(nums)` 与 `numTxt(v)`；rating 文案改为
  `N 人评分 · 平均 X · 中位数 Y 分`。
- 浏览器实测：奇数 [1,2,5,5,5] → 平均 3.6 / 中位数 5；
  偶数 [1,2,4,5,5,5] → 平均 3.7 / 中位数 4.5；空态 → 双 `—`。
- 设计文档加了硬约束：数值型组件（rating/scale）**必须并列给出平均与中位数**，
  差值 > 1 判为两极分化并高亮。理由：平均会被极端值拽跑，
  [1,2,4,5,5,5] 看平均像"反响一般"，实际多数人打高分被两个低分拉低。

## 顺手修掉的真 bug：投票归属错节点

`wire()` 里的点击委托原先用 `vote(cur().id, ...)`，即**不管点哪个节点的星星/选项，
票一律记到当前节点**。画布上多个节点同时可见，点邻居页投票 → 票记错页；
若当前页恰好没有投票组件则 `vote()` 直接 return，**票静默丢失**。
已改为从 `e.target.closest('.fd-node')` 反推所属节点（`.fd-pin` 的点击同理）。
实测：当前页 n1 时点 n4 星星与 n2 选项，票分别正确落到 n4 / n2。

## 本地验证环境的坑（下次绕开）
- Bash 里用 `(python3 -m http.server ... &)` 起的静态服务，**会在该轮命令结束时被回收**，
  后续 curl 得到 502、浏览器看到空白页。必须用 `run_in_background: true` 启动。
- 传给 `agent-browser eval` 的脚本里别写 `!!`——zsh 会做历史展开导致脚本报错，
  用 `> 0` 或直接判 truthy 代替。
- 一次 grep 里用 `\|` 组合多个中文模式有概率匹配为空，拆成几条独立 grep 更稳。
